> 使用 AI 修改代码、配置、SQL、脚本或文档前，必须阅读仓库根目录 `AGENTS.md`、[AI 开发规范](角色文档/后端开发/AI开发规范.md) 和 [AI 开发提示词](角色文档/后端开发/AI开发提示词.md)。

## 2. 服务职责

API 负责：

- 用户注册、登录、token 刷新和退出。
- JWT、Redis session、并发会话上限、即时失效和密码版本同步。
- 用户资料读取和稳定身份索引定位。
- 请求校验、统一业务码、中英文消息和 Trace 回传。
- 可选请求/响应签名、字段级加解密和防重放。
- 配置热加载状态和受控内网操作；`sys_config` 读取链路作为基础能力保留，当前业务 route/logic 尚未启用。
- 存活、就绪、指标和供 Admin 代理的内网文档资源。
- 认证风控事件的脱敏采集与 Kafka 投递。

API 不负责：

- 管理员账号、MFA、RBAC、后台审计和运营页面。
- Asynq Worker、Scheduler、工作流和离线批处理。
- 大表无边界查询、全量导出、数据回填或在线 DDL。
- 通过公网暴露运维接口或文档资源。

跨服务按以下职责分工实现：API 只产生前台业务事实和轻量事件，Admin 承担后台控制面与异步执行；禁止在 API 请求链路内复制 Admin 的任务运行时，也禁止由 Admin 反向承接面向用户的同步请求。

## 3. 请求链路

```text
public listener
  -> route spec
  -> recovery / trace / access log
  -> security chain (none | public | auth)
  -> handler parse + Validate
  -> logic use case + transaction/cache
  -> model / Redis / Collector
  -> internal/httpresp.JSONResp

internal listener
  -> private source + optional allowlist
  -> Ops token + HMAC + timestamp + Redis nonce
  -> internal handler
```

HTTP 响应统一使用：

```json
{
  "status": true,
  "code": 1,
  "message": "成功",
  "data": {},
  "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
  "spanId": "00f067aa0ba902b7"
}
```

前端反馈必须保留 `traceId`，便于与访问日志、业务日志、审计事件和 Trace 平台关联。HTTP 状态表示协议层结果，`code` 表示稳定业务语义，两者不能互相替代。

## 5. 安全链路

| chain | 使用场景 | 核心校验 |
| --- | --- | --- |
| `none` | 存活、就绪、指标 | 不进入前台签名、加密或 JWT 链；指标只注册到内网监听器，探针仍依赖部署网络边界 |
| `public` | 注册、登录等未登录入口 | 按 RouteSecurityPolicy 执行签名、加密、限流和防重放 |
| `auth` | 用户资料、刷新、退出 | 前台安全策略 + JWT + Redis session/版本校验 |
| `internal` | 配置热加载、内网文档资源 | 私网来源、Ops token、HMAC、5 分钟窗口、Redis nonce；跨主机生产使用 mTLS |

前端只按 `docs/site/route_security_manifest.json` 中的 alias、method、path 和字段策略实现安全链。未知路由必须返回空策略，不能降级到整包签名、整包加密或 `*`。

## 6. 配置与运行边界

- 主配置来自 `etc/config.yaml`；示例分别在 `etc/config.sample.yaml` 和 `etc/config.dnmp.sample.yaml`。
- HTTP listener、`app_id/app_key`、JWT、安全密钥、MySQL、Redis、Collector 和组件注册属于启动期能力，变化后重启。
- 已注册的运行时应用器可以处理受控热加载字段；状态接口返回 `restartRequired=true` 时必须按原因统一重启。
- 新增全局业务运行期配置时复用现有 `sys_config`、登记 key 和类型化 getter；当前没有生产业务调用方，不得把初始化表或注册清单描述为运行期已启用。
- Redis Key 集中在 `common/rediskeys`，不在 handler/logic 临时拼通配 key。

## 7. 开发闭环

新增或修改接口时必须同步：

1. `types` 请求/响应、校验和 JSON 字段。
2. 模块 `RouteSpecs`、稳定 alias、RouteMeta 和 access chain。
3. `RouteSecurityPolicies` 与 `route_security_manifest.json`。
4. handler、logic、model/cache/infra 的真实调用链。
5. 业务码、HTTP 映射、中英文 i18n 和日志字段。
6. 接口文档中的请求、响应、安全字段、业务码和示例。
7. 前端 route policy、类型和安全测试向量。
8. 聚焦测试、`go test ./...`、`git diff --check` 和发布说明。

详细文件落点与示例见[开发扩展指南](角色文档/后端开发/开发扩展指南.md)。

## 8. 部署验收

发布前至少确认：

- `admin-go` 与 `api-go` 当前分支名相同；两端归一化后的 `user.route_shard_count` 相等，分表候选方案、身份索引和物理表路由处于同一发布阶段，任一不一致时停止发布。
- 初始化或补齐未登记资产时按 `migrate-status -> migrate-dry-run -> migrate-bootstrap` 执行，并核对真实结构/数据；修改已有列、索引或数据时由 DBA/运维工单记录 SQL SHA-256、影响行数和校验结果，候选版本不包含一次性增量 SQL。
- `/api/live` 返回 HTTP 2xx 且不访问外部依赖；`/api/ready` 返回 HTTP 2xx，所有 enabled 组件为 ready，disabled 组件不被误报为 failure。
- 认证冒烟覆盖登录、刷新、退出和资料读取：刷新后旧 token 不能再次刷新，退出后目标 Redis session 失效，错误 token 返回既定业务码。
- 限流验证覆盖账号/IP 阈值与 429 业务码；Redis 不可用时认证安全路径按设计失败关闭，不能静默绕过。
- 重新生成后端清单并与 `route_security_manifest.json` 比较为零差异；前端安全向量逐 alias 验证签名/加密字段、顺序、空值和密钥版本。
- 从发布网络确认 internal listener 无公网路由；合法 Ops HMAC 请求成功，错误 token、过期 timestamp 和重复 nonce 失败，跨主机生产链路完成 mTLS 证书校验。
- `/api/metrics` 可被内网 Prometheus 抓取且公网拒绝；一次冒烟请求可用 `trace_id` 关联访问日志和 Trace；启用 Collector/告警时分别验证 Kafka 成功计数和一条受控告警。

完整构建、迁移、灰度和回滚步骤见[部署发布指南](角色文档/运维/部署发布指南.md)。

## 9. 文档维护规则

- 文档只描述当前代码、配置和部署资产可证明的行为。
- 接口文档按调用任务拆分，概览负责导航，字段级文档负责完整契约；同一事实只保留一个权威来源。
- 命令、路径、字段、默认值、上限和示例必须从当前仓库验证。
- 变更路由时同步 RouteSpecs、alias、RouteMeta、manifest、接口文档和测试；变更安全字段时再同步前端 policy/type/向量；变更配置、Model/初始化 SQL 或 Redis Key 时分别同步样例/重启说明、DBA 交付和 helper/TTL/失效测试，并记录实际验证命令。
- 删除能力时同步删除文档、侧栏、路由安全快照、文档权限资源和失效测试。
- 不记录“最近已通过”等没有候选版本与日志快照的临时结论。
