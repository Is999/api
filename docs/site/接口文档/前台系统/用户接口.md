# 用户接口

## 当前用户资料

`GET /api/user/profile`

### 请求头

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| Authorization | string | 是 |  | `Bearer <token>` |

### 安全字段

| 项目 | 字段 |
|------|------|
| 请求签名字段 | 不参与签名 |
| 请求加密字段 | 不参与加密 |
| 响应签名字段 | email, phone |
| 响应加密字段 | email, phone |

### 响应示例

```json
{
  "status": true,
  "code": 1110,
  "message": "获取成功",
  "data": {
    "id": "778919762005200896",
    "shardNo": 896,
    "username": "demo_user",
    "nickname": "Demo",
    "email": "de***o@example.com",
    "phone": "138****0000",
    "avatar": "",
    "status": 1,
    "lastLoginAt": "2026-06-02 12:00:00",
    "lastLoginIp": "127.0.0.1",
    "createdAt": "2026-06-02 12:00:00",
    "updatedAt": "2026-06-02 12:00:00"
  }
}
```

### data 内部字段

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| id | string | 是 |  | 用户雪花 ID，以字符串返回，避免前端 JS 安全整数精度丢失 |
| shardNo | int | 是 |  | 用户 ID 哈希分片号，固定由 `CRC32(雪花 ID 字符串) % 1024` 生成，范围 `0-1023`，用于后续用户分表、并发分片查询和分片游标查询 |
| username | string | 是 |  | 用户名，注册时裁剪首尾空白并限制为 3-32 个 Unicode 字符 |
| nickname | string | 是 |  | 昵称 |
| email | string | 是 |  | 邮箱脱敏展示值 |
| phone | string | 是 |  | 手机号脱敏展示值 |
| avatar | string | 是 |  | 头像 |
| status | int | 是 |  | 状态：1 正常，0 禁用 |
| lastLoginAt | string | 否 |  | 最后登录时间 |
| lastLoginIp | string | 否 |  | 最后登录 IP |
| createdAt | string | 是 |  | 创建时间 |
| updatedAt | string | 是 |  | 更新时间 |

用户登录先按身份类型选择 `user_identity_username/user_identity_email/user_identity_phone/user_identity_oauth` 身份目录：用户名按 `identity_value` 定位，邮箱和手机号按 `identity_hash` 定位，三方登录按 `provider/identity_value` 定位。按已知用户 ID 查询时，应用先根据固定桶和 `user.route_shard_count` 选定一个物理表，再以账号身份目录 `LEFT JOIN` 该表完成单次读取；身份索引缺失和主表记录缺失仍分别返回错误。身份目录只保存稳定的 `user_id/user_shard_no`，不保存物理拓扑快照。

## 内网同步用户运行态

`POST /internal/users/:id/runtime-sync`

该接口为内网运维路由，不允许公网访问；仅用于 admin 后台直接修改 `user` 表后，通知 API 进程失效用户资料缓存或登录态。敏感变更必须先在数据库事务中单调递增并提交 `user.auth_version`，再携带已提交的新版本调用本接口清理 Redis；数据库版本是并发窗口内的最终失败关闭边界。用户表增删改仍由各自服务或后台 DB 管理，不通过该接口代理。

### 路径参数

| 字段 | 类型 | 是否必须 | 字段解释 |
|------|------|----------|----------|
| id | int64 | 是 | 正整数用户 ID，只从路径读取；正文和查询参数中的同名字段不改变同步对象 |

### 请求头

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| Content-Type | string | 是 | application/json | 非空请求体固定为 `application/json` |
| X-Ops-Token | string | 是 |  | 运维接口令牌，需匹配 `ops.config_reload_token` |
| X-Ops-Timestamp | string | 是 |  | Unix 秒时间戳，参与运维 HMAC 签名 |
| X-Ops-Nonce | string | 是 |  | 每次请求生成的 16 字节随机数，使用 32 位小写十六进制编码 |
| X-Ops-Body-SHA256 | string | 是 |  | 请求体 SHA256 十六进制摘要，空 body 按空字节计算 |
| X-Ops-Signature | string | 是 |  | 使用 `ops.config_reload_token` 对 `method\nrequestURI\ntimestamp\nnonce\nbodySHA256` 计算 HMAC-SHA256 |

### 请求体

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| profile | bool | 否 | true | 是否失效用户资料缓存；`profile` 和 `sessions` 都为 false 时默认按 true 处理 |
| sessions | bool | 否 | false | 是否失效该用户全部登录态 |
| authVersion | uint64 | 条件必填 |  | `sessions=true` 时必填，必须是 admin 敏感变更事务已提交的新认证版本 |
| reason | string | 否 |  | 同步原因，仅用于日志排查，最大 128 字符 |

`profile=true` 时复用该用户的资料回源锁，最多用 3 秒获取锁后精确删除缓存，防止已开始的旧回源重新发布资料；请求取消、锁竞争耗尽或 Redis 故障时返回失败，调用方应重试同步。

### 安全字段

| 项目 | 字段 |
|------|------|
| 请求签名字段 | 不参与签名 |
| 请求加密字段 | 不参与加密 |
| 响应签名字段 | 不参与签名 |
| 响应加密字段 | 不参与加密 |

### 响应示例

```json
{
  "status": true,
  "code": 1106,
  "message": "更新成功",
  "data": {
    "userId": "778919762005200896",
    "authVersion": 2,
    "profileCacheInvalidated": true,
    "sessionsInvalidated": true,
    "reason": "admin_reset_user_password"
  }
}
```

### data 字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| userId | string | 是 |  | 用户雪花 ID，以字符串返回，避免前端 JS 安全整数精度丢失 |
| authVersion | uint64 | 是 | 0 | 本次登录态失效使用的已提交认证版本；仅清资料缓存时为 0 |
| profileCacheInvalidated | bool | 是 | false | 是否已处理用户资料缓存 |
| sessionsInvalidated | bool | 是 | false | 是否已处理登录态 |
| reason | string | 否 |  | 本次同步原因 |
